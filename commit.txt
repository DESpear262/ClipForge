feat: stabilize video loading (asset URL + Blob fallback), fix fs capabilities, add diagnostics

PR #5 - HTML5 Video Preview (stabilization)

Key changes:
- VideoPlayer now resolves sources via `convertFileSrc()` (asset protocol) and gracefully falls back to a Blob when `asset.localhost` is unavailable in dev.
- Implemented MIME-aware Blob fallback using `@tauri-apps/plugin-fs.readFile` (mp4/webm/mov), with CSP support for `blob:` already configured.
- Fixed plugin-fs capabilities: replaced invalid scoped entries with `fs:read-all` plus a global `fs:scope` allow list to permit reads from user-selected paths (e.g., `C:\**`).
- Added extensive diagnostics in `VideoPlayer`: HEAD preflight logs for asset URL, media event listeners (canplay/loadedmetadata/stalled/waiting/etc.), and readyState/networkState dumps. This greatly improves troubleshooting.

Files modified:
- src/components/VideoPlayer.tsx – Source resolution, Blob fallback, diagnostic logging, event-state tracing.
- src-tauri/capabilities/fs-read.json – Proper `fs:read-all` + `fs:scope` configuration.
- docs/memory-bank/* – Updated architecture docs: media loading flow, capabilities, dev-mode behavior, and current status.

Notes:
- In some dev environments, WebView2 refuses `asset.localhost` (ERR_CONNECTION_REFUSED). This is benign: the player now falls back to Blob and playback continues.
- Production builds typically serve asset URLs successfully.
